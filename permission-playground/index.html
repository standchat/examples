The rules behind this sandbox +
Workspace membership is required for every role, including administrators. An assignment never grants access across workspaces. Only administrators can see archived records or delete projects.
Customers can read active, shared projects belonging to their customer account. Teammates can read and update active projects in their workspace. Contractor controls change contractor access only; the workspace-wide option broadens reading, while updating still requires assignment.
There is no real login, database, policy deployment, or permission enforcement here. In a real application these checks belong on the server or database, with tests for your actual data and trust boundaries.

      


      

        
03 / MAKE IT YOURS
Context is the integration.
This example combines a deterministic local preview with a complete, inline Stand conversation. No framework or consumer build step.

          
Try the full loop
  1. Switch to Customer, then Contractor. Inspect the denied placeholders as well as the visible projects.
  2. Select Workspace-wide and inspect proj_03. Reading becomes allowed for contractors, but updating still requires assignment.
  3. Select “Discuss my requirement,” edit the draft, and choose Send. Changing a control alone never sends the scenario.
  4. Change the identity or policy and send a follow-up. Each message carries a new snapshot; the existing conversation stays in place.

          
Copy the complete folder
npx degit standchat/examples/permission-playground my-rowhaven
cd my-rowhaven
python3 -m http.server 8000
Open http://localhost:8000/. Keep the HTML, CSS, and all five JavaScript files together. The two /_shared/ references and <sx-example-bar> provide gallery chrome only; remove them when copying to your site. The playground and chat work without them.

          
Connect your own Stand site
Replace site: 'demo' in app.js with the Site ID from your installation snippet in Stand’s Sites. Configure an eligible AI Stand-in or human responder for the domain. The shared demo connects to Stand’s AI and does not appear in your account.

          
const client = new ScenarioClient(
  { site: 'demo', scope: 'rowhaven-permissions-v1' },
  () => scenarioContext(state)
);
const chat = document.createElement('stand-inline');
chat.client = client;
chat.setAttribute('look', 'field');
chat.setAttribute('grow', 'unfold');
document.querySelector('#chat-mount').append(chat);

          
Carry context through supported APIs
conversation.js attaches the selected record, identity, policy, decisions, and assumptions to each visitor message. The initial session also includes a short prompt. These are discussion context, never authentication or executable policy. The two local Stand files handle discovery, HTTP sends, WebSocket replies, handoffs, attribution, and recovery.
