    ◇ What needs a decision
      Read the rehearsal assumptions
      We match a small, fixed set of familiar status names to Backlog, Ready, In progress, In review, or Done. With Custom statuses selected, your labels remain unchanged. Unknown names, repeated names, approval gates, and Done before another step need review.
      Reporting adds a decision about metrics and history. Approvals without an approval column adds a decision about gate placement. Counts describe these rules, never migration readiness. Tickets, attachments, history, permissions, automations, and report data are not imported or verified.

      BEHIND THE EXAMPLE
      How it works
      This plain HTML, CSS, and JavaScript example pairs a deterministic workflow rehearsal with a real custom Stand Chat client. Edit columns, use the grip or arrow buttons to reorder, and select a proposed mapping. Only Send starts a conversation or shares your current rehearsal.
      Copy the whole folder
      npx degit standchat/examples/migration-rehearsal my-threadlane
      Serve the copied folder over HTTP with any static server; no install or build is needed. All product styles and conversation code are local. The optional /_shared/ stylesheet and script provide the example bar and code-copy buttons. They can be removed on your own site.
      Use your own Stand site
      Replace data-stand-id="demo" in the script tag with the Site ID from Sites in Stand. The custom client reads that same ID. Demo conversations use Stand's shared AI and do not appear in your account. Your own site is needed for your knowledge, human routing, and history.
      Context travels with the question
      import { getClient } from './stand-visitor.js';
const client = getClient({
  site: 'demo', scope: 'threadlane-migration-v1'
});
client.subscribe(renderConversation);
client.mount(); // discovery or same-tab recovery
// Only inside the visitor's submit handler:
await client.send(question + '\n\n' + contextFor(board, selected), {
  owner: selected,
  prompt: 'Fictional rehearsal. Discuss blockers; do not promise an import.'
});
      app.js renders text safely and keeps one conversation across mappings. stand-visitor.js handles session creation, HTTP sends, WebSocket replies, handoffs, follow-ups, and recovery. Replies never execute code or modify the board.
      Board, draft, and conversation recovery use session storage in this tab when available; otherwise they last for this page only. The custom interface owns its presentation. The retained Stand script uses the repository's demo configuration; this interface calls the documented visitor API directly.
