Behind the canvas

How it works

The page is the starting point. Stand is the conversation.

Try it

  1. Change the specimen’s palette, layout, or spacing. Pricing controls calculate a local estimate.
  2. Choose Comment, then click a spot or use the three target buttons. Each target also has a keyboard-focusable selection surface.
  3. Review the attached context. Write a question and choose Start conversation to send it to Stand.
  4. Close the panel to keep browsing; reopen its pin to return. End conversation actually ends the session. Escape closes the panel, then exits comment mode.

Each target has its own session and draft. The context snapshot is captured when you first select the target. Before sending, you can update it under View attached context. A snapshot stays attached to that thread; later design or pricing edits do not silently change what was sent. Pin positions and context are kept in session storage when available.

Honest by design

Framefield, its features, and prices are invented. The specimen and estimates run locally. Replies come from Stand’s real shared demo AI, labeled as AI. Human handoff and email follow-up appear only when Stand sends the corresponding event; test these with your own registered site and responders. AI replies cannot edit the page.

Copy this example

npx degit standchat/examples/comment-the-page my-canvas

Serve the folder with any static server. No install or build step. Keep index.html, style.css, app.js, model.js, and stand-visitor.js together. The optional /_shared/ files only provide the examples bar.

Context, attached at the first send

import { getClient } from './stand-visitor.js';
import { conversationPrompt } from './model.js';

const client = getClient({
  site: 'demo',
  scope: 'framefield:design',
});
client.mount(); // discovery, not a conversation

// Only after the visitor chooses to send:
await client.send(question, {
  owner: 'design',
  prompt: conversationPrompt(contextSnapshot),
  analyticsId: 'framefield-design',
});

Replace demo in the Stand script’s data-stand-id with your Site ID from Sites; the app reads that attribute. Configure your responders and registered domain in Stand. The prompt is supported context, not a secret or a control channel.

The local client uses HTTP for sends, a WebSocket for replies, and authenticated reads for recovery. It preserves message IDs on retries and asks before repeating an uncertain start. Text uses textContent; outbound links allow HTTP(S) only.
