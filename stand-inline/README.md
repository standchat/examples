# Stand Inline

A custom chat UI for [Stand Chat](https://stand.chat/): one element, `<stand-inline>`, that puts
the whole conversation inside your page, right where the question comes up. It starts anywhere
from a line of text to a full hero, and grows with the conversation. Studio, reference and seven
example pages: https://examples.stand.chat/stand-inline/

```html
<script type="module" src="/stand-inline.js"></script>

<stand-inline site="YOUR-SITE-ID" look="field" placeholder="Ask about this product"></stand-inline>
```

## What to copy

| File | What it is |
| --- | --- |
| `stand-inline.js` | The element: looks, growth, rendering, theming. Needs `stand-visitor.js` next to it. |
| `stand-visitor.js` | The conversation client for Stand's visitor API (beta). No DOM, so it works with any framework. |

The rest is this example's own site: `index.html`, `style.css` and `studio.js` (the studio),
`samples.js` and `demo.js` (scripted sample conversations), `canvas.html` (the studio's blank
page), and one folder per example page.

## Try it before you have a Site ID

`site="demo"` connects to Stand Chat's demo Stand-in on any domain, including localhost. Its
conversations don't appear in your account. Switch to your own Site ID, from **Sites** in Stand,
to have your own Stand-ins and team answer.

## How this was made

Everything in this folder was generated by Claude Opus 5.5 at max effort in Claude Code, in a
single session, from one prompt (plus one follow-up asking for this note). The prompt, with typos
fixed:

> Add a custom chat UI to the examples collection that is easy to embed in context. While
> `stand-card` only starts a chat, this should keep the whole conversation in context, a bit like
> the one at the top of https://stand.chat/guide/custom-chat-ui.
>
> Differences to that example:
>
> - It should be more polished: actually a great tool for many different purposes on a site.
> - Make it customizable: easy to adapt to any style.
> - Find innovative variations, from a barely noticeable start that grows progressively during
>   the chat, to impossible to ignore on the page.
>
> Come up with 5–10 different use cases or contexts where it can be used, and generate an example
> of each. If needed, make one page for each (under the same example), or make it more like a
> studio for tuning the experience.
>
> This should feel like a polished add-on product to Stand Chat, not a one-off experiment.
> Something people would actually like to use on their sites to get their visitors chatting.

What made it work: the [custom chat UI guide](https://stand.chat/guide/custom-chat-ui) is written
as a contract for coding agents; `site="demo"` gives a real conversation from localhost; scripted
samples make the hard states (handoffs, email follow-ups) visible; and every page was checked in a
browser at desktop and phone sizes.
