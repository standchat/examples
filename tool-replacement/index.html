THE HONEST DETAILS

A workspace, with edges.

Dayfolio is an invented business, and this is its defined capability set. The comparison is a conversation starter, not a recommendation to cancel a subscription.

In this fictional product

Shared pages and comments, linked knowledge and search, tasks with owners and dates, simple boards, and tables with basic filters.

Outside its scope

Offline editing, formulas, advanced permissions, automatic migrations, recording, live integrations, and dependency scheduling.

Assumes a small team, online use, workspace-wide access, and manual copying and setup. Check real requirements before moving work.

HOW IT WORKS

The question stays beside the work.

This plain HTML, CSS, and JavaScript example combines a deterministic local comparison with a real Stand conversation. The desk never pretends to be an AI answer.

Try it

  1. Add tools to your shelf and drag one to the desk. The Compare buttons provide the same action with a keyboard or touch.
  2. Select the features you rely on and describe the one you would miss. The fit note uses fixed rules in model.js.
  3. Send a question in the attached chat. Only this action creates a conversation and sends your comparison context.
  4. Switch tools and return: each has its own conversation. Active comparisons are locked to their original assumptions. End the chat to edit them. Reset planner clears local choices when no conversation is active.

The integration

Local copies of stand-inline.js and stand-visitor.js implement the Stand Visitor API beta contract: availability, HTTP sends, WebSocket replies, session recovery, delivery retries, responder identities, notices, and handoff/follow-up cards. The demo Site ID connects only to Stand’s shared AI; testing your own team’s handoffs requires your own configured site.

// One conversation per tool. Context is read at the first send.
chat.setAttribute('site', SITE_ID);
chat.setAttribute('scope', `dayfolio-${toolId}`);
chat.setAttribute('prompt', contextFor(state));
chat.setAttribute('look', 'field');
chat.setAttribute('grow', 'unfold');

Context is capped below the API’s 2,000-character prompt limit. It includes the fictional boundaries, tool, use case, shelf, dependencies, assumptions, and feature note. The visitor’s question is the actual message. Arbitrary text is rendered with text nodes. No model output is interpreted as page commands.

Copy this example

npx degit standchat/examples/tool-replacement my-dayfolio

Serve that folder with any static server; consumers need no install or build step. Set SITE_ID in model.js and replace the Stand script’s Site ID in index.html with yours from Sites in Stand. Keep the returned notices and attribution. Remove the two /_shared/ includes and <sx-example-bar> when copying; they provide gallery chrome only. Every functional asset is in this folder.

Selections and visitor session credentials use separate sessionStorage entries. If storage is blocked, the page continues in memory. Don’t include secrets in feature notes. Local comparison state is never sent before a visitor chooses Send.
