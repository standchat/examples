Why Molehill.doc

Why Molehill?

Most analytics tools make a mountain out of your data. We make molehills: small, specific answers you can act on before lunch.

One hill, six tools

Analytics, replays, flags, experiments, surveys and a warehouse share one SDK, one list of people and one bill. When a funnel dips, the replays of the people who fell out are a click away.

Your data stays yours

Pick US or EU hosting when you sign up. The core is open source (MIT), so you can run it on your own servers instead. We don't sell data. We barely share snacks.

Priced like a utility

Every product has a free allowance that resets each month. Past it, you pay per event, recording or response, and a cap per product stops the bill where you say.

Who shouldn't use Molehill

If you need a 90-slide deck every quarter, we'll disappoint you. If you need to know why signups dipped last Tuesday, you're in the right hole.

Molehill Setup

There's nothing to install. Molehill is made up.

The chat is real, though: it runs on Stand's Visitor API, and the section below this desktop shows how it's built.

How it's built ↓

    Molehill is a fictional company. This desktop demonstrates a custom chat UI on Stand Chat's Visitor API.

    How it works

    Let visitors hand you the thing they're confused about

    Questions on a website are rarely general. They're about one row of the pricing table, a dip in a chart, a line in the changelog. Here, visitors can drag any of those onto the chat. It rides along with the question as an attachment, so whoever answers sees exactly what the visitor was looking at, and the reply can open the window it talks about.

    The desktop is plain HTML, CSS and JavaScript in this folder, with no dependencies and no build step. The conversation is real: it runs on Stand's Visitor API, so an AI Stand-in answers and someone from the team can take over.

    Try it

    1. Grab a row of Pricing.sheet, a point on the chart in Product analytics or a line of Changelog.txt, and drop it on Chat. It lands as a chip above the message box. Collect a few, then ask.
    2. Watch the reply. Names in it are chips too: Pricing.sheet › Session replay opens that window next to the chat and lights up the row.
    3. No mouse? Tab to a row or a line and press Enter to attach it, or Shift + F10 for its menu. On a phone, tap anything in an app, then Ask about this.
    4. Ask something, then minimize Chat right away. The mole digs while the answer is on its way, and pops up with a flag when it lands. Reload: windows, attachments and the conversation all come back.
    This page uses site: 'demo', Stand Chat's shared demo site, which works on any domain. Its demo Stand-in follows this page's prompt, including Molehill's made-up prices. With your own Site ID, your own Stand-ins and team answer, and every question shows up in Stand's History with its attachments.

    1. Mark what can be asked about

    Anything with a data-ask attribute can be dragged onto the chat, or attached with the keyboard or the ⋯ menu. The attribute names the thing; data-val is a short preview of what it showed. The window around it supplies the source, and data-alias adds names a reply might use for it.

    <section class="win" data-win="pricing" data-names="Pricing.sheet|Pricing">
  <tr data-ask="Session replay" data-alias="Replay|Recordings">…</tr>
</section>

<section class="win" data-win="changelog" data-names="Changelog.txt|Changelog">
  <li data-ask="2026-09-08" data-val="Session replay: heatmaps on top of recordings">…</li>
</section>

    What each kind of thing carries, as the preview in parentheses:

    • A pricing row: its free tier and unit price, plus your usage and bill once you've typed an estimate in Your usage.
    • A week on the chart: that week's three numbers and any annotation. Grab near a line and you get just that series' point.
    • A changelog line, a feature flag, a replay event, a funnel step: what it shows right now. Flip a flag off, and its row says so.
    • A desktop icon, or the icon in a window's title bar: the whole app or file.
    • Text you selected, dropped on Chat: a quote, with the window it came from.

    drag.js handles the gesture with pointer events: a small move starts a drag with a mouse, a long press with a finger. It draws the ghost, lights up any [data-drop="chat"] under the pointer, and flies the ghost into the message box on drop. Desktop icons and title-bar icons attach a whole app or file.

    2. Attachments are lines of the message

    The Visitor API sends text, and that's enough. Each attachment becomes one line at the top of the message: a 📎, where it came from, what it is, and its preview in parentheses. People on the team read it as is in Stand; the page parses it back into chips, in the transcript and after a reload.

    📎 Pricing.sheet › Session replay (5,000 recordings free/mo, then $0.005 each · your usage 8,000 → $15.00/mo)
📎 Changelog.txt › 2026-09-08 (Session replay: heatmaps on top of recordings)

    export const MARK = '📎';

// { source: 'Pricing.sheet', item: 'Session replay', value: '5,000 recordings…' }
export function attachmentLine({ source, item, value }) {
  return `${MARK} ${[source, item].filter(Boolean).join(' › ')}${value ? ` (${value})` : ''}`;
}

export function formatMessage({ attachments = [], text = '' }) {
  return [...attachments.map(attachmentLine), text.trim()].filter(Boolean).join('\n');
}

// Lines that start with the marker are attachments; everything else is the question.
export function parseMessage(body) {
  const attachments = [];
  const text = [];
  for (const line of body.split('\n')) {
    if (line.startsWith(`${MARK} `)) attachments.push(parseAttachment(line));
    else text.push(line);
  }
  return { attachments, text: text.join('\n').trim() };
}

    The first message also stores private context for whoever answers, and that context can't change later. Attachments ride in each message instead, so the fifth question carries its own context as clearly as the first.

    3. Replies that open windows

    The prompt asks the Stand-in to name a window or a row in double square brackets when it helps. resolve() matches the name against the windows' data-names and the rows' data-ask and data-alias, ignoring case and file extensions. A match becomes a chip that opens the window and lights up the row; a name the page doesn't know stays plain text. When a new reply arrives, its first reference opens beside the chat by itself, without taking the keyboard focus away from the message box.

    // "…then $0.005 each [[Pricing.sheet: Session replay]]." → text, a chip, text
for (const part of parseReply(message.body)) {
  if (part.ref) {
    const target = desktop.resolve(part.ref); // { win: 'pricing', el: <tr> } or null
    bubble.append(target ? refChip(part.ref, target) : part.ref);
  } else {
    bubble.append(formatText(part.text)); // escaped, then paragraphs, lists, bold, code, links
  }
}
if (isNew && firstTarget) desktop.reveal(firstTarget, { beside: 'chat', focus: false });

    References only ever open, focus and highlight things on the page. Nothing in a reply runs code or follows a link by itself.

    4. The prompt

    Sent once, with the first message, as private context (at most 2,000 characters). It gives the Stand-in Molehill's facts, the attachment format and the window names. The last line describes the desktop at that moment; it's live below.

    5. What the team learns

    A question that arrives with its row, chart point or changelog line attached needs no "which plan did you mean?". Over a few weeks, the attachments in Stand's History add up to a map of what confuses people: which pricing rows get dragged most, which chart gets asked about, which release notes raise eyebrows. That's the product learning a plain chat box never gets.

    6. The conversation behind it

    stand-visitor.js is the network side, copied from the stand-inline example: discovery, one-time creation, sends over HTTP, replies over a WebSocket, and recovery after reloads and dropped connections. Chat just renders its state. The unsent message, attachments included, is the client's draft, so it survives a reload too.

    import { getClient } from './stand-visitor.js';

const client = getClient({ site: 'demo' }); // Your Site ID from Stand goes here.
client.subscribe((state) => chat.render(state));
client.mount(); // Asks who can answer, or restores the conversation.

// On send: the first message starts the conversation, with the prompt.
client.setDraft('');
const context = () => ({ open: desktop.openNames(), estimate: apps.estimate() });
await client.send(formatMessage(composer), { prompt: buildPrompt(context()) });

    Good to know

    • Honest about who answers. Chat shows the responder's name as Stand gives it and an AI badge while the AI Stand-in answers. If someone from the team joins, the badge changes and the transcript says so. The mole is Molehill's mascot, not the responder: it never speaks in the chat.
    • The demo attaches nothing. On a first visit, a pointer drags a pricing row onto Chat to show the idea. The row lands as a suggestion marked Demo, outside the message, and joins a question only if you click Attach. A drag of your own or a sent question clears it.
    • Closing isn't ending. Closing or minimizing Chat keeps the conversation going, and the mole tells you when a reply lands. End conversation in Chat's ⋯ menu ends it in Stand.
    • A reload keeps everything. The transcript and the unsent message come back from the client's sessionStorage; window positions, flag toggles and your usage estimate from this page's own entry. Without storage it all works, and forgets on reload.
    • Nobody around. If Stand finds no one to answer, Chat says so and offers to check again, and the mole dozes off. Drags still collect attachments; they just wait.
    • Keyboard and screen readers. Every draggable is focusable with a name, Enter attaches it, Shift + F10 opens its menu, and arrow keys move between rows. Esc closes menus and cancels a drag. Whole replies are announced, not letters.
    • Reduced motion. No ghost flying across the screen, no digging: attachments appear in place, the mole holds still, and the replay doesn't autoplay.
    • It's a beta. The Visitor API can grow new fields and events. The client ignores what it doesn't know.

    This example's brief

    A product analytics suite whose website is a playful retro desktop: icons, draggable windows, a menu bar, cheeky copy. Its chat is one more app window. The interaction: drag anything on the desktop onto the chat to ask about it. An app icon, a chart, a pricing row, a changelog line lands as an attachment chip, and the team sees exactly what the visitor was looking at. Keyboard, right-click and long-press do the same. Attachments travel as a parseable prefix in the message text and come back as chips after a reload. Replies name windows in [[double brackets]], which open and highlight them. An original mole lives in a molehill in the corner: it peeks, digs while the answer is being written, and pops up with a flag when a reply arrives. On phones the desktop becomes a home screen of apps.

    If you try this yourself

    • Point your agent at the custom chat UI guide and start on the demo Site ID, so it can hold real conversations while it builds.
    • Keep context in the message text, in a format both people and code can read. A fixed marker at the start of a line is easy to parse, and the team never needs a special viewer.
    • Name the page's parts in the prompt, then test replies for real. Here the Stand-in used the window names reliably once the prompt showed a few examples of the format, and the resolver forgives the rest: extensions, case, aliases.
    • Make the drag testable: this one uses pointer events rather than native drag and drop, so a headless browser can drive it, and touch gets a long press instead of fighting the scroll.
