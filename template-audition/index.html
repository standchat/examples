BEHIND THE BUILD

How it works

A preview you can disagree with.

Type a business name and description, switch templates, and try desktop or mobile width. Desktop fills the available canvas; mobile caps it at 375 pixels. Each layout is authored HTML and CSS. There is no model-generated design, scoring, or inferred preference.

Keep saves a choice. Wrong and Missing open an inline thread at that section. Choose “look & feel,” “story,” or both, leave a note, then send your question. Every send includes a fresh, visible snapshot of your business, selected layout, section, choices, notes, and assumptions.

A real conversation, with clear boundaries.

The local stand-inline.js and stand-visitor.js use Stand’s visitor API (beta). Separate scopes keep the nine section threads apart. They preserve drafts, recover sessions, reconcile messages, and show availability, failures, AI/human identity, handoffs, and offered email follow-up.

Site ID demo uses Stand’s shared AI Stand-in. It may discuss the context, but isn’t configured as a Foldcraft designer and cannot edit the preview. Your own Site ID is needed for your team, knowledge, and instructions. Conversation recovery uses this tab’s session storage; if storage is unavailable it lasts only for this page.

Copy the complete folder

npx degit standchat/examples/template-audition my-audition

Serve that folder from any static HTTP server. No installation or build step is needed. Keep index.html, style.css, app.js, model.js, and both Stand files together. The /_shared/ assets only add this repository’s example bar and can be removed when copied.

Connect your Stand site

Replace SITE_ID = 'demo' in app.js and the Stand script’s data-stand-id in this page with the Site ID from Sites in Stand. Configure an eligible responder and register your real domain.

// A separate thread at each section.
chat.setAttribute('site', SITE_ID);
chat.setAttribute('scope',
  `foldcraft-${template}-${section}`);

// This folder adds a local pre-send hook.
chat.addEventListener('stand-before-send', event => {
  event.detail.text = conversationText(
    state, template, section, event.detail.text
  );
});

The hook builds a regular visitor text message; it is a local component extension, not a Stand API event. The supplied widget script remains for the example bar’s status. The actual conversation uses the inline client.
